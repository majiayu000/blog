从蒸馏、合成数据到 RSI：模型竞争真正比拼的是什么？

当训练基础设施逐渐标准化，竞争重心正在从单点算法技巧，移向数据策略、可执行评估，以及能否把失败证据稳定地变成下一轮改进。

精读：42章经嘉宾：孟繁青主题：POST-TRAINING · DATA · RSI
原节目：从蒸馏到合成数据到 RSI，模型竞争的下一个焦点是什么？

42章经对谈 Evolvent AI 联合创始人孟繁青，发布于 2026 年 8 月 8 日。本篇是基于节目内容与公开研究资料写成的原创精读，不是逐字稿转载。

在小宇宙收听 ↗
Answer first

蒸馏、合成数据和 RSI 不是三个分散的热点，而是模型把外部能力逐步内化、再尝试自己改进自己的三个阶段。真正稀缺的也不再只是一次训练，而是发现缺口、生产数据、验证效果、保留最佳结果的完整闭环。

这期节目最有价值的地方，不是又解释了一遍什么叫后训练，而是把几条通常分开讨论的线连了起来：模型厂为什么越来越重视数据，做 Post-training 的人为什么容易走向 Agent 与 Benchmark，国内模型追赶究竟靠不靠蒸馏，以及 RSI 为什么听起来宏大，落地时却首先变成一个非常工程化的实验系统。

孟繁青给出的答案很鲜明：训练本身正在服务化，数据研究反而成为后训练的主要工作；蒸馏是加速器，不是能力的唯一来源；RSI 的近期形态，也不是模型突然获得无限自我进化能力，而是把“发现问题—造数据—训练—评估”这条链逐步交给 Agent。

三个词，其实是一条能力内化路径

01 / DISTILL

蒸馏

借助更强模型的输出，把已有能力更快迁移给目标模型。

→
02 / SYNTHESIZE

合成数据

围绕能力缺口主动设计题目、轨迹、反馈与难度，而不只是复制答案。

→
03 / SELF-IMPROVE

RSI

让系统根据评估证据，自己提出并验证下一轮改进策略。

从“向老师学”到“自己出训练题”，再到“自己管理研究循环”。自动化范围逐步扩大，验证难度也同步上升。

蒸馏解决的是速度问题：如果强模型已经表现出某种能力，目标模型可以学习它产生的答案、推理轨迹或工具使用过程。它是获取合成数据的一种手段，但二者不能画等号。

合成数据解决的是供给问题：当高质量自然数据越来越难获得，团队必须主动构造符合训练目标的数据分布。真正困难的不是“让模型多生成一些文本”，而是判断该生成什么、难度是否合适、有没有奖励投机，以及训练后是否伤害了别的能力。

RSI（Recursive Self-Improvement）解决的是研究循环问题：系统不只生成数据，还要从失败中提出假设、改变数据策略、训练候选模型、读取评估反馈，并决定继续搜索还是回到历史最佳版本。

后训练正在变成“数据研究”

在成熟模型厂里，SFT、推理服务和评估流水线会逐步平台化。研究员不必每次从找机器、配环境开始，而是向统一服务提交数据与配置。基础设施没有消失，它只是从每个人都要重复完成的工作，变成了由专门团队维护的公共能力。

因此，后训练人员的注意力会向上游移动：模型到底缺什么能力？应该构造什么训练经验？怎样过滤错误与投机轨迹？数据混合和课程难度如何安排？节目里那句“Post-training 的人每天主要在做数据”，并不是说研究变简单了，而是说研究对象变了。

SHIFT 01

从题库到环境

旧式 Benchmark 更像闭卷考试，输入问题、比对答案。Agent Benchmark 则要提供软件、状态和工具，让模型在长流程里完成真实任务。

SHIFT 02

从单分到证据链

最终结果之外，还要观察中间操作、状态变化、约束是否满足，以及模型有没有通过漏洞获得表面高分。

SHIFT 03

从清洗到课程设计

数据质量不只是“正确或错误”。太简单学不到新东西，太难又无法形成有效梯度，能力提升还可能以其他任务退化为代价。

SHIFT 04

从一次训练到实验组合

单次结果很难说明是哪项策略起效。数据、训练、评估和预算必须被固定或记录，才有可能做可靠归因。

后训练的壁垒没有因为基础设施成熟而消失。壁垒只是从“能不能把模型训起来”，转移到了“能不能持续提出有价值的数据假设”。

模型竞争最后拼什么？

节目里最反直觉的判断，是国内外模型差距的来源。直觉上，国内团队更擅长工程，因此后训练应该更占优势；孟繁青的观察却相反：国内更有特色的部分可能是被算力约束倒逼出来的预训练架构创新，而海外团队由于更早开始积累高质量后训练数据，反而在数据与组织经验上拥有时间优势。

这个判断未必能简单推广到所有公司，但它提醒我们，模型竞争至少有四层，而且每一层的时间常数不同：

竞争层核心问题追赶方式难复制之处
算力能跑多大规模、多少实验资本投入与资源调度供给、集群稳定性、长期预算
架构每单位算力能换来多少能力论文、开源与人才流动规模化验证和工程细节
数据模型应该学习什么蒸馏、合成、采集与标注失败经验、课程设计、质量判断
组织能否把新认知快速变成新版本流程调整与团队协作决策速度、反馈链路、隐性知识

蒸馏为什么只是加速器

蒸馏能把强模型已经显露出来的能力快速变成训练材料，尤其适合缩短后训练的数据冷启动时间。但它无法代替全部能力来源：预训练仍然决定基础知识与表示能力，自己的评估体系决定团队能否发现真正的缺口，而架构与训练系统决定这些数据能否被有效吸收。

因此，“是否使用蒸馏”不是最有信息量的问题。更重要的是：团队是否知道自己在蒸馏什么，能否验证迁移后的能力，以及当外部教师不可用时，能否靠自己的模型、环境和反馈继续生产有效数据。

RSI 距离真正的闭环，还有多远？

把 RSI 拆开看，它并不神秘。一个最小的数据中心自我改进循环，大致只有五步：

诊断能力缺口
提出数据假设
生成并验证数据
训练候选模型
评估并选择

难点在于，这条链不是天然单调向上的。模型可能误判失败原因，生成与真实任务错位的数据，训练出格式更漂亮但能力更差的候选，也可能在已经找到好版本后继续搜索，最后提交一个退化版本。

Evolvent AI 公开的 RSIBench-Data 论文刻意把外围系统固定下来：基础模型、训练与推理服务、评估环境和预算保持一致，只允许研究 Agent 改变训练数据策略。这样做不是为了模拟无限制的自我进化，而是先回答一个可验证的问题：Agent 能不能根据反馈，稳定地做出更好的数据研究决策？

58.33%在 24 个 Agent×任务设置中，有 14 个通过后续迭代超过了第一次有效尝试。
78.26%在达到峰值后仍继续搜索的设置中，最终一次尝试低于历史最佳；其余也只是回到同一峰值。

这组结果揭示的不是“RSI 已经成功”或“RSI 完全没用”，而是一条更有价值的中间结论：当前 Agent 已经偶尔能发现有效改进，但还不能可靠地管理改进过程。发现能力开始出现，搜索、归因和最佳结果保护仍然不稳定。

我的解读：短期内，RSI 最先创造价值的地方可能不是让一个基础模型无限自我升级，而是替研究团队提高实验吞吐——自动生成候选、执行验证、整理失败证据，并在严格边界内探索数据策略。它更像研究基础设施的升级，而不是突然到来的智能奇点。

这期节目最值得带走的五个观点

  1. 训练门槛降低，不等于研究门槛降低。当训练服务被标准化，真正困难的工作会上移到能力诊断、数据策略和评估设计。
  2. Agent Benchmark 本身已经接近产品原型。它需要重建工具、状态和验证器，因此优秀的评估环境往往离真实业务也更近。
  3. 数据质量最终仍要经过训练验证。静态规则能挡住明显错误，却很难提前判断一批数据是否真的提升目标能力、是否损害其他能力。
  4. 蒸馏解决的是追赶速度，不是全部能力来源。真正可持续的竞争力来自自己的基础模型、数据生产、评估体系与组织反馈。
  5. RSI 的核心不是“自己改代码”，而是“自己管理证据”。能否从失败形成正确假设、保持实验可归因，并保住历史最佳结果，比盲目增加迭代轮数更重要。

听完以后，仍需保留的三个边界

一、预训练与后训练不是泾渭分明

“预训练学知识、后训练做分布迁移”是有用的简化，但真实系统里两者会相互影响。持续预训练、中期训练、长上下文扩展和大规模 RL 已经让边界越来越模糊。不能据此推出基础能力只来自某一个阶段。

二、Benchmark 接近真实，不代表等于真实

环境越复杂，验证器越可能遗漏真实世界的隐含要求。一个 Agent 在模拟 Notion、终端或代码仓库里完成任务，并不自动意味着它能在真实组织中稳定工作。评估仍然只是被明确写下来的那部分需求。

三、“蒸馏不是决定性因素”是判断，不是已证实比例

各家训练数据、教师模型调用和内部评估并不透明，很难给蒸馏贡献一个可靠占比。更稳妥的结论是：蒸馏很重要，但没有充分证据证明它可以替代预训练、架构创新和自主数据积累。
